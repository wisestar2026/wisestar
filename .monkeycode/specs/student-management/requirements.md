# 学员管理模块 需求文档

Feature Name: student-management
Updated: 2026-08-12

## Introduction

学员管理模块包含两个子模块：**学员注册（新增学员）** 与 **订单管理（开通 AI 自习室权限）**。本模块完成学员信息入库、自动生成学员学号作为登录账号，并通过订单为学员开通 AI 自习室使用权限（学科 / 年级 / 教材版本 / 账号时长）。学员端按订单授权的范围访问内容，多条有效订单的权限合并生效，账号到期后权限自动失效。

本需求文档基于用户提供的《学员管理模块 开发需求文档》（2026-08-12）整理，采用 EARS 语法规范化。

## Glossary

- **学员（Student）**：通过本模块注册入库的学习者，登录账号为系统生成的 8 位学号。
- **学号（StudentNo）**：学员唯一身份标识，由系统自动生成的 8 位数字，全局唯一，不允许人工修改。
- **订单（Order）**：为学员开通 AI 自习室权限的记录，关联学员主键，配置学科、年级、教材版本与账号有效期。
- **学员权限（StudentPermission）**：订单生效后的权限明细，记录学员可访问的学科、年级、教材版本与有效期，用于学员端鉴权。
- **教材版本（Version）**：学科下的教材版本（如人教版、苏教版）。
- **账号时长（Duration）**：订单授予的使用有效期，到期后对应使用权限自动失效。
- **校区（Campus）**：本次迭代仅保留表结构字段与页面下拉组件，不开发校区业务逻辑。

## Requirements

### R1. 学员注册

**User Story:** AS 管理员，I want 录入学员基础信息并保存，SO THAT 学员信息入库且自动生成登录账号。

#### Acceptance Criteria

1. WHEN 管理员提交新增学员表单，the system SHALL 校验姓名非空、联系号码非空后写入学员主数据表。
2. WHEN 新增学员成功，the system SHALL 自动生成 8 位数字学号（全局唯一），并作为学员端登录账号。
3. WHEN 新增学员成功，the system SHALL 为该学员创建默认登录账号，初始密码固定为 123456。
4. WHEN 新增学员成功，the system SHALL 返回学员基础信息（含学号）。
5. IF 学号生成时与已有学号重复，the system SHALL 重新生成学号直至唯一。
6. IF 学员姓名与联系号码组合已存在，the system SHALL 拒绝新增并返回重复提示。
7. WHEN 新增失败，the system SHALL 返回对应的错误提示。
8. WHILE 学号作为唯一身份标识，the system SHALL 在数据库层对学号设置唯一索引，防止重复。

#### 字段说明

| 字段 | 必填 | 说明 |
|---|---|---|
| 学号 | 否（系统生成） | 8 位数字，系统自动生成，页面不可编辑 |
| 姓名 | 是 | 学员真实姓名 |
| 年龄 | 否 | 学员年龄 |
| 联系号码 | 是 | 学员联系手机号 |
| 学校 | 否 | 学员所在学校 |
| 校区 | 否 | 页面展示下拉列表，本次不开发业务逻辑 |

数据库层预留扩展字段，用于后续数据分析使用，前端页面本次不展示。

### R2. 订单管理（开通 AI 自习室权限）

**User Story:** AS 管理员，I want 为已注册学员创建订单并配置学科、年级、教材版本与账号时长，SO THAT 学员获得对应范围的使用权限。

#### Acceptance Criteria

1. WHEN 管理员创建订单，the system SHALL 关联已注册学员的主键 ID。
2. WHEN 管理员配置订单，the system SHALL 支持学科多选、年级多选、教材版本单选、账号时长配置。
3. WHEN 订单保存成功，the system SHALL 将权限相关数据写入学员权限关联表。
4. WHEN 学员登录学员端，the system SHALL 仅允许访问订单配置授予的学科、年级、教材版本对应的内容。
5. WHILE 账号未到期，the system SHALL 保持对应使用权限生效。
6. IF 账号到期，the system SHALL 自动失效对应使用权限。
7. WHEN 同一学员存在多条有效订单，the system SHALL 合并多条订单的权限生效。
8. WHEN 订单保存，the system SHALL 在订单主表存储订单基础信息，并在学员-权限关联表存储可访问范围与有效期，以学员表主键 ID 作为外键关联。

### R3. 账号与密码规则

1. WHEN 学员新增完成，the system SHALL 使用学号作为学员端登录账号。
2. WHEN 学员首次登录，the system SHALL 使用默认初始密码 123456。
3. WHEN 学员登录学员端后修改密码，the system SHALL 以学员新密码替代默认密码。

### R4. 校区（本迭代仅占位）

1. WHEN 新增学员页面展示校区字段，the system SHALL 仅展示下拉组件。
2. WHILE 本迭代未接入校区管理模块，the system SHALL 不开发校区业务逻辑与数据维护。

## 边界约束（Non-Functional）

1. 学号只能系统自动生成，人工不可编辑。
2. 学号需数据库层唯一性校验（唯一索引）。
3. 姓名与联系号码需组合重复性校验，防止同一学员重复录入。
4. 学员权限中间表保存学员生效权限，用于学员端鉴权校验。

## Open Questions（待确认）

1. 学员端（/student）当前为纯前端 mock，本次迭代是否包含「学员端按订单权限过滤可访问内容」的真实鉴权？
2. 学科 / 年级 / 教材版本的数据来源（学科取知识管理 t_subject？年级与教材版本用固定枚举还是自由文本）？
3. 学员账号的 user_type 与登录跳转规则（学员登录后仅可进入学员端？管理员仅可进入管理端？）。

## 已确认决策（2026-08-12）

1. **迭代范围**：本次仅实现管理端（学员注册 + 订单管理 + 权限表落库）；学员端（/student）为纯前端 mock，按订单权限的内容鉴权过滤留待后续迭代接真实接口。
2. **字典数据源**：学科取知识管理 `t_subject`（语文/数学/英语）；年级用固定枚举（一年级 ~ 六年级）；教材版本用固定枚举（人教版 / 苏教版 / 北师大版 / 外研版）。
3. **账号体系**：新增学员账号 `user_type = Student`（扩展 `AppConsts.USER_TYPE` 枚举）；登录复用现有 `POST /api/public/login`；登录成功后前端按 userType 跳转——Student 跳 `/student`，SysUser 跳管理端；管理端路由仅 SysUser 可访问。
