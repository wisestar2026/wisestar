# Requirements Document

## Introduction

AI 自习室系统当前已具备出题、组卷、答题、批改能力，但题目与答题数据缺乏结构化的"知识点"维度，无法支撑后续对学生答题情况做"优势/薄弱知识点"分析。

本需求为数据分析打好数据基础，分三个层面落地：

1. 题目数据结构：为每道题补充结构化知识点、难度等分析所需字段
2. 答题明细数据：提交答卷时按题落库，记录每题对错、知识点、得分、用时
3. 前端题目管理：表格展示与分析相关字段，支持按知识点筛选

## Glossary

- **系统**: AI 自习室系统（wisestar）
- **题目**: 题库中的单道试题，存储于 `t_template` 表
- **学科**: 知识点第一级维度，如 数学、语文、英语、物理
- **章节**: 知识点第二级维度，如 第二章
- **知识点**: 知识点第三级维度，如 函数，一道题可关联多个知识点
- **难度**: 题目难度等级（简单/中等/困难）
- **答题明细**: 一次答卷中单道题的作答记录，存储于 `t_answer_detail` 表
- **学生**: 完成问卷/考试的答题用户

## Requirements

### Requirement 1: 题目知识属性

**User Story:** AS 教师/管理员, I want 为题目配置知识点和难度, so that 后续能按知识点统计分析学生答题情况

#### Acceptance Criteria

1. WHEN 教师创建或编辑题目, 系统 SHALL 提供知识点录入能力，知识点采用 学科→章节→知识点 三级结构，一道题可关联多个知识点
2. WHEN 教师创建或编辑题目, 系统 SHALL 提供难度等级选择（简单/中等/困难）
3. WHERE 题目存在, 系统 SHALL 持久化保存学科、章节、知识点与难度属性
4. IF 题目已有答题记录, 修改题目知识点或难度时, 系统 SHALL 保留历史答题明细中原知识点数据

### Requirement 2: 答题明细记录

**User Story:** AS 系统, I want 每次答卷按题记录明细, so that 分析学生正确率、薄弱知识点时无需解析整份 JSON

#### Acceptance Criteria

1. WHEN 学生提交答卷, 系统 SHALL 为答卷中每道题生成一条答题明细记录
2. WHEN 生成答题明细, 系统 SHALL 记录学生、题目、题目类型、知识点、学生答案、是否正确、得分、用时
3. WHERE 题目未配置知识点, 系统 SHALL 在答题明细中记录空知识点
4. IF 判断题/选择题作答, 系统 SHALL 依据正确答案判定对错；IF 填空/文本题, 系统 SHALL 按文本匹配规则判定对错
5. WHEN 学生暂存或重复提交, 系统 SHALL 更新对应答卷的答题明细而不产生重复记录

### Requirement 3: 题目管理表格优化

**User Story:** AS 教师/管理员, I want 在题目管理界面查看和筛选知识点与难度, so that 维护题目分析属性时操作直观

#### Acceptance Criteria

1. WHEN 教师打开题目管理页, 系统 SHALL 在表格中展示每道题的知识点与难度列
2. WHEN 教师按知识点筛选, 系统 SHALL 返回包含该知识点的题目列表
3. WHEN 教师编辑题目, 系统 SHALL 支持修改知识点与难度

### Requirement 4: 数据分析查询基础

**User Story:** AS 系统, I want 提供按知识点聚合的统计查询能力, so that 后续优势/薄弱分析可直接消费

#### Acceptance Criteria

1. WHEN 查询某知识点统计, 系统 SHALL 返回该知识点的答题次数、正确次数、正确率
2. WHEN 查询学生知识点画像, 系统 SHALL 按知识点返回该学生各知识点的正确率
3. WHEN 统计查询, 系统 SHALL 支持按学生、按知识点、按题目三个维度聚合
