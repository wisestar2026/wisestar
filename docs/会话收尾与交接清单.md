# 会话收尾与交接清单

> 用途：每次开发会话结束前（或交接给下一次对话前）按本清单执行，确保三件事——**项目文档最新、main 主线最新、数据库可迁移到下一个对话**。
> 下一次对话开始时，可先读本文件 + `docs/开发维护日志.md` + `.monkeycode/SESSION_CONTEXT.md` 快速进入状态。

## 一、前提信息

- 仓库根：`/workspace`（仓库直接位于工作区根）；唯一开发主线：`main`。
- 后端 jar：`server/api/target/wisestar-v1.9.0.jar`
- H2 运行库：`server/api/wisestar.mv.db`（被 `.gitignore` 忽略，容器重建即丢失）
- H2 快照：`server/db-snapshot/wisestar.sql`（入库，供新环境恢复）
- 预览端口：前端 `3000`、后端 `1991`；导出/恢复脚本 `server/db-export.sh`、`server/start-preview.sh`

## 二、步骤

### 1. 确保项目文档最新

按本次改动性质同步对应文档：

- 类/方法变化 → `docs/项目词典-后端-{shared,rdbms,api,ai,flow}.md`
- 接口/权限点变化 → `docs/项目词典-接口.md`
- 前端文件增删 → `docs/项目词典-前端.md`（顶部声明覆盖的 `.js/.jsx` 文件数）
- 结构/表 → `docs/项目结构梳理.md`、`docs/项目词典.md`
- 过程记录 → `docs/开发维护日志.md`（追加新节，保持时间顺序），并同步 `docs/README.md` 第二节索引里的节号
- 新功能需求/设计 → `.monkeycode/specs/<YYYY-MM-DD>-<功能>/requirements.md` 与 `design.md`

自检命令：

```bash
cd /workspace

# 前端 .js/.jsx 文件数（应与 docs/项目词典-前端.md 顶部声明一致）
git ls-files 'wisestar-client/src/*.js' 'wisestar-client/src/*.jsx' 'wisestar-client/src/**/*.js' 'wisestar-client/src/**/*.jsx' | sort -u | wc -l

# 开发维护日志最新节号（应与 docs/README.md 索引一致）
grep -nE "^## [0-9]+\." docs/开发维护日志.md | tail -1
```

### 2. 确保 main 主线最新（构建 → 校验 → 提交 → 推送）

```bash
# 后端构建（必须 clean，防止旧 jar 残留）
cd /workspace/server && MAVEN_OPTS="-Xmx768m -XX:MaxMetaspaceSize=256m" mvn clean package -pl api -am -DskipTests

# 前端 lint + 构建
cd /workspace/wisestar-client && npm run lint && npm run build
```

- 期望：后端 `BUILD SUCCESS`；前端 `oxlint` 0 error、`npm run build` 成功。
- `oxlint` 存在既有基线告警（分布于旧文件），本次改动文件必须 0 error 且 0 warning。
- 逐文件 `git add <file>`（**禁止** `git add -A` / `git add .`），按主题分组提交，信息格式 `<type>(<scope>): <中文描述>`。
- push 前与用户确认；本仓库为 GitHub，**不带** `-o merge_request.*` 参数：

```bash
cd /workspace && git push origin main
```

- 若 push 报 `RPC failed; HTTP 408` / `unexpected disconnect`，先重试；仍失败则加大缓冲：

```bash
git -c http.version=HTTP/1.1 -c http.postBuffer=524288000 push origin main
```

- 校验本地与远程一致：

```bash
cd /workspace && git status -sb && git rev-parse HEAD origin/main
```

`git status -sb` 显示 `## main...origin/main`（无 ahead/behind），且上方两条 rev-parse 输出相同，即主线最新。

### 3. 确保数据库可迁移到下一个对话

H2 文件库单进程独占，**导出前必须先停后端**。

```bash
# 1) 停止预览后端：使用后台终端 kill（terminal_id），不要用 pkill/killall

# 2) 确认已停（pgrep 会误匹配正在执行该命令的 shell，改用 ps 过滤）
ps -eo args | grep -E '[j]ava .*wisestar-v1\.9\.0\.jar' || echo "NO BACKEND RUNNING"

# 3) 导出快照
cd /workspace/server && ./db-export.sh

# 4) 检查差异：正常应仅为运行期数据；若出现建表/改表语句需先确认种子脚本已同步
cd /workspace && git diff --stat -- server/db-snapshot/wisestar.sql
git diff -- server/db-snapshot/wisestar.sql | grep -E "^[+-].*(CREATE TABLE|DROP TABLE|ALTER TABLE.*ADD COLUMN|CREATE INDEX)" || echo "NO SCHEMA CHANGES"

# 5) 提交并推送
git add server/db-snapshot/wisestar.sql && git commit -m "chore(db): 重导 H2 快照（<说明>）" && git push origin main
```

新环境/下一次对话用 `server/start-preview.sh` 启动：库文件缺失且快照存在时，脚本会先 `RunScript` 导入快照（并把 `--spring.sql.init.mode` 置为 `never`）再启动，从而找回上一会话的数据。

### 4. 重启预览并自检

```bash
# 后台终端运行
cd /workspace/server && ./start-preview.sh

# 健康检查
curl -s -o /dev/null -w "api:%{http_code}\n" http://localhost:1991/api/healthcheck
curl -s -o /dev/null -w "web:%{http_code}\n" http://localhost:3000/
```

期望 `api:200` / `web:200`。后端启动日志末尾应出现 `Undertow started on port(s) 1991` 与 `Started SurveyServerApplication`。

## 四、新环境初始化（git clone 后）

```bash
git clone https://github.com/wisestar2026/wisestar.git
cd wisestar

# 1) 后端构建（生成 api/target/wisestar-v1.9.0.jar）
cd server && MAVEN_OPTS="-Xmx768m -XX:MaxMetaspaceSize=256m" mvn clean package -pl api -am -DskipTests

# 2) 启动后端（库文件缺失时自动从快照 server/db-snapshot/wisestar.sql 恢复）
./start-preview.sh

# 3) 前端
cd ../wisestar-client
printf 'API_TARGET=http://localhost:1991\n' > .env.local
npm ci
npm run dev
```

- 端口与文件存储已在 `application.yml` / `application-preview.yml` 配置，无需手动创建 `server/api/application.properties`。
- 默认账号：管理员 `admin / 123456`，学员 `a000001 / 123456`。

以下内容**不在 git 中**，全新环境需按说明处理：

| 内容 | 位置 | 处理方式 |
| --- | --- | --- |
| 上传的文件/图片 | `server/api/files/`（约 800MB，被 `.gitignore` 忽略） | 无法入库；新环境需另行拷贝该目录，否则 `t_file` 引用的图片（`/api/file` 接口）会 404 |
| 前端依赖 | `wisestar-client/node_modules/` | `npm ci` |
| 后端构建产物 | `server/api/target/` 等 | `mvn clean package` |
| 本地环境变量 | `wisestar-client/.env.local` | 按上文命令创建 |
| H2 运行库 | `server/api/wisestar.mv.db` | 由快照自动恢复，无需手动拷贝 |
| 浏览器会话 | Cookie `sk-token` | 重新登录 |

## 五、注意事项

- H2 文件库单进程独占，禁止启用 `AUTO_SERVER`（本容器主机名为 UUID，`InetAddress.getLocalHost()` 解析失败会导致启动直接报错）。
- 预览 profile 的 `spring.sql.init.mode` 见 `server/rdbms/.../config/application-preview.yml`；`start-preview.sh` 在库文件已存在时仍传 `always`，故 `init-h2.sql` 中新增的幂等 DDL（`CREATE TABLE IF NOT EXISTS` / `ADD COLUMN IF NOT EXISTS`）重启预览后端即自动应用；但 live 库新增表/数据后仍必须重导快照。
- 种子脚本 `server/rdbms/src/main/resources/scripts/init-h2.sql` 与 `init-mysql.sql` 必须同步修改。
- 后端构建后必须重启预览后端，运行中的 JVM 不会自动加载新 jar。
