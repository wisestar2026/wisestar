## 六、建议的物理整理（待确认后执行）

现状为**扁平目录 + 一次性文档较多**。建议做一次目录归类（用 `git mv` 保留历史，并同步更新引用）：

```text
docs/
├── README.md                      # 本索引
├── 项目结构梳理.md
├── 架构稳定性评估与改造方案.md
├── 项目词典.md / 项目词典-接口.md / 项目词典-后端-*.md / 项目词典-前端.md
├── 需求与规则/                     # 学生端需求、积分学币、学习评价、导入模板、AI 教辅模板
├── 模块导读/                       # 完整操作链路、两份源码讲解
├── 历史归档/                       # 开发维护日志、开发路线图、Java 速查手册
└── assets/                        # images/、exam.jpg、preview.*、wechat.jpeg
```

> 执行前需确认：是否接受上述目录划分，是否保留原文件名的引用方式（会同步更新 `README.md` 与 `.monkeycode/SESSION_CONTEXT.md` 中的路径）。

## 七、维护约定

1. 代码改动影响结构/接口/表时，同步更新对应词典文件（见第一节"何时更新"）。
2. 新功能的需求/设计文档放入 `.monkeycode/specs/<日期>-<功能>/`。
3. 过程记录写在 `开发维护日志.md`，保持时间顺序。
4. 不再适用的文档移入「历史归档」，不要直接删除。
