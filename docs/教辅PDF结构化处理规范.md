## 1. 术语与四种数据形态

| 术语 | 含义 |
|---|---|
| 学科 / 章节 / 小节 / 知识点 | 系统四级知识结构；学科为系统内置字典，其余三级由导入建立 |
| 题库（repo） | 题目的归属容器；一道题归一个 `repoId` |
| 题空标记 | 填空题干中的作答空位，统一写作 `__①__`、`__②__` … 按出现顺序递延 |
| STD | 循环小数标准存储格式：循环节半角括号纯文本，如 `0.(6)`、`3.4(897)` |
| DISPLAY | 循环小数显示格式：教材循环点记法，如 `0.6̇`、`3.48̇9̇7̇`（组合点 U+0307） |
| INPUT | 学员作答可接受的多种写法（循环点 / 括号 / 省略号 / 有限小数） |
| OBJ | 判题中间对象：`{kind, int, nonrep, rep}` 或 `{kind:'finite', int, frac}` |
| 门禁 | 交付前必须逐项通过的校验清单（第 9 节） |

循环小数四形态由前端 `wisestar-client/src/utils/cycleDecimal.js` 实现，详见第 7 节。

## 2. 输入与教材框架

### 2.1 输入

- 教辅 PDF（含答案册）；扫描件须以 ≥300dpi 渲染为页面图后**视觉读取**（识别图形/表格/公式），不得只依赖文本层。
- 随书元数据：出版社、学科、年级、学期（上/下）、教材版本。
- 教材清单（示例，按实际批次替换）：

| 教材 | 原版本 | 处理结论 |
|---|---|---|
| 53 天天练试卷 | 旧人教版 | 按知识点内容归入 2024 新人教版唯一框架 |
| 小状元作业本（2 册） | 2024 新人教版 | 直接入框架 |
| 小状元测试卷（2 册） | 2024 新人教版 | 直接入框架 |
| 一本测试卷（2 册） | 2024 新人教版 | 直接入框架 |

### 2.2 唯一框架

- 全部内容归入**一套教材版本框架**（示例：2024 新人教版 8 章）。
- 旧版独有内容（如「位置」数对、「简易方程」）**不单列章节**，按考察内容归入新版对应小节，并在 05 异常清单登记。
- 章节数量、名称、顺序以已建成的系统章节字典为准（导入前先对齐）。

## 3. 总体流程

```text
阶段0 教材解析 → 阶段1 知识树构建 → 阶段2 题目提取 → 阶段3 题目改编
→ 阶段4 图片处理 → 阶段5 构建 Excel → 阶段6 验证 → 阶段7 图片上传回填
→ 阶段8 系统导入（先建树、后导题）
```

| 阶段 | 输入 | 关键动作 | 输出 |
|---|---|---|---|
| 0 教材解析 | 教材 PDF（含答案册） | 渲染页面、视觉读取题目/图形、标注出处（书/页码/题号） | 结构化数据文件 |
| 1 知识树构建 | 教材目录 + 各书交叉印证 | 建 章节→小节→知识点 三级；跨书覆盖数 + 重点程度分级 | 知识树（01/02/03 的源数据） |
| 2 题目提取 | 教材页面 | 全量提取，每题标注 知识点/出处/题型/题干/选项/答案/解析/图片 | 题目数据 |
| 3 题目改编 | 题目数据 | 题型归并、拆分/合并、空号重排、答案简洁化、解析增强（第 5 节） | 改编后数据 |
| 4 图片处理 | 原书页面图 | 按题裁剪特指图形（去题号/标题/选项）；纯文字题不配图 | 裁剪图片目录 + manifest |
| 5 构建 Excel | 改编数据 + 知识树 | 汇总生成 01~05（第 6 节） | 5 张 Excel |
| 6 验证 | 全部产物 | 第 9 节门禁 | 验证报告 |
| 7 图片上传回填 | 裁剪图片 | 逐张上传取 URL，回填题目「图片」列 | 图片 URL 映射 |
| 8 系统导入 | 已通过门禁的 Excel | 先导入 01/02/03 建树，再导入 04 题目 | 系统内数据 |

> 硬约束：系统导入题目时，章节 / 小节 / 知识点**必须是系统中已存在的名称**（不自动新建）。因此阶段 8 必须「先章节 → 再小节 → 再知识点 → 最后题目」，顺序不可颠倒。

## 4. 三级知识体系规范

### 4.1 结构与系统载体

| 层级 | 系统表 | 关键字段 | 教材粒度 |
|---|---|---|---|
| 学科 | `t_subject` | name / code | 系统内置（语文 1001 / 数学 1002 / 英语 1003） |
| 章节 | `t_chapter` | subjectId / name / grade / term / version / sort | 教材章 |
| 小节 | `t_section` | chapterId / name / sort / grade / term | 教材课时 |
| 知识点 | `t_knowledge_point` | sectionId / name / sort / grade / term / importance / content | 最小考查单元 |

- 题目实体 `t_template` 另有 `chapter` / `section` 文本快照列、`knowledge_point`（JSON 数组文本）多值列，供列表筛选与展示。
- 题目与知识点的结构化关联由 `t_knowledge_point_question` 承担；跨表引用以 ID 关联为准。

### 4.2 命名规则

- 章节：与教材章名一致，固定顺序。
- 小节：教材课时粒度；命名规则 `课时名 + 序号`（如「小数乘小数①/②/③」「解方程」），或独立专题名（如「对比练 小数乘法和小数除法的计算」）。
- 知识点：与教材术语一致（如「小数乘小数的算理」「商的近似数」「分段计费的实际问题」）。

### 4.3 非知识型章节 / 小节（硬规则）

以下类型**不设小节、不作为知识点**，其下题目一律按考察内容归入实际知识小节：

- 整理和复习、单元整体作业、综合练习、练习课、总复习、期末复习、期中检测等。

> 系统落地：这类名称**不要**出现在 01/02/03 中；04 的「章节/小节」列直接填题目实际归属的知识小节。

### 4.4 知识点内容设置（三段式，必填）

统一格式（**单个单元格内存放整段文本**）：

```text
定义：…；经典题型：…；重点板块：…
```

- 定义：准确、一句话讲清概念 / 规则 / 公式。
- 经典题型：列举 2~4 种典型考法。
- 重点板块：易错点、关键方法提示。

> 系统落地：写入知识点导入的第 8 列「内容设置」，后端存为 `content = {"points":["<整段文本>"]}`；不支持该列内嵌图片。

### 4.5 重点程度分级

- 三级：**重点 / 次重点 / 一般**。
- 判定依据：**跨书覆盖数（几套书都考）+ 题目数量权重**；覆盖 ≥2 套书或题量显著者为重点 / 次重点。
- 系统落地：知识点表 `importance` 取值 `core` / `key` / `normal`，对应 重点 / 次重点 / 一般；`t_knowledge_point` 目录导入列**不含重要度**，需通过知识点更新接口设置。
- 「跨书覆盖」为交付表自带列，不入系统字段，保留在 03 交付版与验证报告中。

## 5. 题目改编规范（核心）

### 5.1 题型体系：只允许 5 种

| 规范题型名 | 系统枚举 | 说明 |
|---|---|---|
| 判断题 | `Judge` | 保留原题型；答案 `正确` / `错误` |
| 单选题 | `Radio` | 原书单选；选项 A~H |
| 单项填空 | `FillBlank` | 一问一空，`__①__`，答案唯一 |
| 多选题 | `Checkbox` | 原书多选；选项 A~H |
| 多项填空 | `MultipleBlank` | 一题多空，`__①__`~`__⑫__`，最多 12 空，每空答案唯一 |

- 其余题型（口算、竖式、脱式、计算、连线、简答、解决问题、画图、作图、说理、设计等）一律归并或删除（见 5.2 / 5.3）。
- 系统标准导入**不支持简答题**（`Textarea`），开放题只能改编为填空题或删除并记入 05。

### 5.2 填空题改编规则

1. **简答 → 填空**：一问一空；原问法改写为带空句式（如「答：…」改为「结果是`__①__`」）。
2. **空号格式（硬约束）**：严格用 `__①__`、`__②__`、`__③__` … 递增编号；空号个数 = 答案个数；同一题内不得跳号 / 乱序。
3. **最多 12 空**：一题 ≤ 12 空；超过须拆分（见 5.3），确有必要的在「标签」标「超12空」、「备注」写「超12空续答：…」。
4. **每空唯一答案（硬约束）**：答案必须准确、简洁、表达唯一，禁止：
   - 长串字符串 / 算式过程（如 `50÷2.2≈22.73（元/kg）` → 只填 `22.73`）；
   - 多种表达方式（说明理由、说明观点、开放作答等）；
   - 多值答案（`0或2`、`9或10`、`A和C`）——必须改问法或拆分，确需保留的标「多值答案，需人工复核」。
5. **删除类**（无法改编为唯一答案，一律删除并记入 05）：
   - 画图 / 作图题、连线题、涂色设计题、开放说理题、需自画线段图等；
   - 画 √ / 画图操作题（即使题型标为判断题）；
   - 算式逆向解释问法（「算式…解决的问题是」「…表示什么」「所求的问题是」）；
   - 说理题（「…这样做的道理是」）；
   - 答案需多值列举或括号双表达（「不可能摸到黄球（一定摸到红球）」）；
   - 答案本身含算式 / 字母代数式（如 `90÷1.25÷2`、`阴影面积=a²-b²`）；
   - 竖式算理 / 方法补充类文字填空；
   - 估算判断「够吗 / 够不够」类。
6. **只设最终结果空（硬规则）**：题干只对**最终结果**设空，不设过程性 / 中间量空；中间步骤（时段判定、分段数、中间量）一律写入解析。
7. **「选择+填空」混合题**：题干含 `__①__` 的选择题可保留，但空 = 答必须匹配。
8. **条件占位空**：题干中表示「补充条件」的横线（不需作答）用普通下划线 `___`，作答空才用 `__①__`。
9. 循环小数书写 / 记法 / 表示类题**保留**（系统前端支持循环点渲染与输入），答案统一存 STD 括号式，详见第 7 节。

### 5.3 大题拆分与合并规则

先拆分，再合并同类，最终「一题一答、便于学生作答」：

1. **拆分**：大题内含多个独立小问 / 独立算式 / 多道并列小题，拆为独立行；每题空号从 `__①__` 重新编号；题号加后缀。
2. **合并**：拆分后仍属**同模板并列**（口算 / 竖式 / 解方程 / 比较大小等）或**同题干同情境仅小问不同**的残留，合并为一道多项填空：
   - 公共题干提取一次，各小问以 `；` 连接；
   - 空号按出现顺序重排；答案一一对应；图片引用去重保留一次；
   - 标签标「由拆分题合并」。
3. **不合并的边界**：各小问知识点不同；完全独立且图形各异；合并后超 12 空；选择题 / 判断题组不合并。
4. **数字保护**：合并 / 清理时不得误删算式数字（如 `3.08÷2.2` 的 `3.` 不是题号）；子题内小问编号保留。

### 5.4 答案规范

- 简洁唯一值：纯数字优先，必要时为短文字（`不可能`、`钝角三角形`、`250g` 规格名、`1红1蓝` 组合描述，题目本身要求的方程 / 公式 / 字母表达式可保留）。
- 单位 / 算式 / 估算过程 / 理由**一律不进答案列**，移入解析。
- 判断题答案只填 `正确` / `错误`；选择题答案填选项字母。
- **极致简洁（硬规则）**：答案不带引导前缀、不带单位；公式 / 代数式移入解析，答案只留数值；仅保留「题目要求填写」的代数式（如求 `t` 小时行驶多少千米 → `350t`）。
- **循环小数**：一律 STD 括号式，禁止 LaTeX 循环点与 Unicode 组合点，见第 7 节。

### 5.5 解析规范

- 结构：`详细解题步骤（含算式 / 算理 / 思路） + 【考查要点：知识点名称】`。
- 必须详细、有启发性（写算理、易错点、方法）。
- 末尾**必须**附 `【考查要点：…】`（系统不做机器校验，由第 9 节门禁保证）。
- 答案清洗时，原过程式答案内容并入解析，不重复造已有内容。

### 5.6 图片规范（题图对应）

1. **图题对应**：题干含「如图 / 图中 / 下图 / 上图」等 → 核对原书是否有图；有图则裁剪该题**特指的图形**。
2. **裁剪内容**：只保留图形本体，不含题号、标题、选项。
3. **图片承载（硬规则）**：图片地址写在「图片」列（系统第 30 列）；**题干列不内嵌占位符**。一个字格可放多个地址，用换行分隔。
4. **地址形态**：必须是可访问的图片 URL。系统内图片经 `POST /api/file/create` 上传后，用 `GET /api/file?id=<fileId>` 形式引用；也允许公网 `http(s)` 地址。
5. **纯文字题**：不配图、无引用（确需说明的记 05）。
6. **孤儿图**：裁剪目录中未被任何题目引用的图片，清理后再交付（门禁项）。

## 6. 系统入库格式（落地关键）

本节定义**可直接导入 wisestar 的 Excel 格式**。交付的 01~05 中，01/02/03/04 需按下列列定义产出。

### 6.1 01 章节导入（`POST /api/chapter/import`）

只解析第一个 sheet，第 1 行为表头；按「学科名 + 章节名」去重，重复跳过；`sort` 由系统按学科自动递增。

| 列 | 列名 | 必填 | 说明 |
|---|---|---|---|
| 1 | 学科名 | 是 | 系统已有学科名（如 `数学`） |
| 2 | 章节名称 | 是 | 该学科下的章节名 |
| 3 | 年级 | 否 | 如 `五年级` |
| 4 | 学期 | 否 | 如 `上册` |
| 5 | 版本 | 否 | 如 `人教版` |

### 6.2 02 小节导入（`POST /api/section/import`）

要求章节已存在；按「章节 + 小节名」去重。

| 列 | 列名 | 必填 | 说明 |
|---|---|---|---|
| 1 | 学科名 | 是 | |
| 2 | 章节名 | 是 | 必须已存在 |
| 3 | 小节名 | 是 | 该章节下的小节名 |
| 4 | 年级 | 否 | |
| 5 | 学期 | 否 | |

### 6.3 03 知识点导入（`POST /api/knowledge-point/import`）

要求小节已存在；按「小节 + 知识点名」去重。

| 列 | 列名 | 必填 | 说明 |
|---|---|---|---|
| 1 | 学科名 | 是 | |
| 2 | 章节名 | 是 | 必须已存在 |
| 3 | 小节名 | 是 | 必须已存在 |
| 4 | 知识点名 | 是 | 最小考查单元名称 |
| 5 | 排序 | 否 | 默认 1 |
| 6 | 年级 | 否 | |
| 7 | 学期 | 否 | |
| 8 | 内容设置 | 否 | 三段式整段文本（第 4.4 节） |

> 重点程度（`importance`）不在此列，需导入后经知识点更新接口设置（`core` / `key` / `normal`）。

### 6.4 04 题目导入（`POST /api/repo/import`，file + repoId）

- 只解析**第一个 sheet**（建议名「题目列表」），第 1 行为表头。
- **严格 30 列，顺序与名称一字不差**（与后端 `STANDARD_HEADERS` 完全一致）：

| 列序 | 列名 | 必填 | 说明 |
|---|---|---|---|
| 1 | 学科 | 是 | 系统已有学科名，不自动新建 |
| 2 | 题型 | 是 | `判断` / `单选` / `单项填空` / `多选` / `多项填空` |
| 3 | 章节 | 条件 | 须属于该学科；若填小节 / 知识点则必填 |
| 4 | 小节 | 否 | 须属于该章节 |
| 5 | 知识点 | 条件 | 整格优先按一个知识点名精确匹配（名称可含顿号）；整格未命中时按 `\n , ， 、 \| ; ；` 拆分多个逐个校验，全部命中才通过 |
| 6 | 题目 | 是 | 题干文本；填空题须已含 `__①__` 标记 |
| 7~14 | 选项A~选项H | 选择必填 | 仅单选 / 多选读取；须从选项A 起连续、无空缺、无重复、至少 2 个 |
| 15 | 难易程度 | 否 | `简单` / `中等` / `困难`（亦接受 `易`/`中`/`难`、`easy`/`medium`/`hard`） |
| 16~27 | 正确答案1~正确答案12 | 是 | 见下方题型规则；多项填空最多 12 空 |
| 28 | 解析 | 否 | 富内容；建议附 `【考查要点：…】` |
| 29 | 标签 | 否 | 多个用 `\n , ， 、 \| ; ；` 分隔 |
| 30 | 图片 | 否 | 图片 URL；多个用换行或逗号分隔，写入 `attribute.examImages` |

**题型与答案填写规则**：

| 题型 | 选项列 | 正确答案列 | 示例 |
|---|---|---|---|
| 判断 | 留空 | 正确答案1 填 `正确` / `错误`（兼容 `对/错`、`true/false`、`1/0`、`√/×`，落库归一到 `正确/错误`） | `正确` |
| 单选 | 选项A~H | 正确答案1 填选项字母或选项内容（仅 1 个） | `B` |
| 多选 | 选项A~H | 正确答案1~12 依次各填一个字母 / 内容（不得重复） | `A`、`C`（分两列） |
| 单项填空 | 留空 | 正确答案1 填唯一答案（只能 1 个，空数须为 1） | `3.14` |
| 多项填空 | 留空 | 正确答案1~12 按空位顺序各填一空（1~12 个） | `5x`、`3y`（分两列） |

**关键判定说明**：

- 多项填空的空数 = 正确答案列中非空单元格的个数（按序 `|` 拼接）；题干 `__①__` 标记数仅作展示，系统不解析，两者必须人工保持一致。
- 单选 / 判断的判分模式为 `onlyOne`，多选 / 填空为 `selectAll`，填空匹配规则 `completeSame`。
- 标准导入固定 `mode = exam`，`repoId` 取导入请求参数。

**行级校验（任一行不通过，整次导入中止并回报行号，最多展示 20 条）**：学科存在、章节归属、小节归属、知识点归属、题型合法、选项连续无重复、答案与题型匹配、单选 / 判断答案唯一、多选答案不重复、空数 ≤ 12。

## 7. 循环小数规范

系统前端已支持循环点渲染与学员端循环点输入（方案 B）。存储、显示、输入、判题四类形态如下。

| 形态 | 名称 | 示例 | 用途 |
|---|---|---|---|
| STD（存储 / 标准） | 循环节括号纯文本 | `0.(6)`、`3.4(897)`、`0.5(10)`、`0.61(8)`、`4.6(05)` | 题目库答案列、题干 / 选项 / 解析文本、接口传输、判题基准 |
| DISPLAY（显示） | 教材循环点记法 | `0.6̇`、`3.48̇9̇7̇` | 前端渲染产物（不落库） |
| INPUT（输入） | 学员可提交的多种写法 | `0.6̇`、`0.666…`、`0.(6)`、`0.666` | 输入器生成值或键盘文本 |
| OBJ（判题对象） | 结构化对象 | `{kind:'cycle', int:'0', nonrep:'', rep:'6'}` | 归一化与判定的中间形态 |

### 7.1 STD 语法

- 形式：`整数部分.非循环部分(循环节)`，循环节用半角括号紧跟，循环节取**最短**（如 `0.666…` 只写 `0.(6)`，不写 `0.(66)`）。
- 循环节从十分位开始 → 非循环部分为空：`0.(6)`、`5.(36)`、`2.(10)`。
- 循环节前有数字照写：`3.4(897)`、`0.5(10)`、`0.61(8)`、`4.6(05)`、`0.0(15)`。

### 7.2 落库硬约束（禁止项）

- 禁止 LaTeX 循环点（`\dot{}`、`$\dot{A}$`）、上划线等数学排版符号进入题干 / 选项 / 答案 / 解析。
- 禁止 Unicode 组合循环点（U+0307）进入**被存储的文本**；一律转 STD 括号式。
- 题干中的循环点记法（`0.ABCABC…`）同步转可读文本（`0.(ABC)`）；选项列同样适用。

> 说明：组合点 U+0307 仅作为前端 DISPLAY 渲染产物与学员 INPUT 出现，不作为存储形态。

### 7.3 判题（数学等价判定）

- 判题比较学员 OBJ 与标准 OBJ，**不做字符串相等**：
  1. 类型一致：均为循环小数或均为有限小数，类型不同直接判错（`0.666` ≠ `0.(6)`）。
  2. 逐位展开比较：取展开位数 `L = max(len(nonrep)+len(rep)*2+4)`，逐位相等即判对。
  3. 近似值类答案（如「保留两位小数」，标准答案为有限小数）走普通有限小数比较。
- 等价输入：`0.666…`、`0.6̇`、`0.(6)` 判对；`0.666`（无循环标记）判错。

### 7.4 系统实现现状与缺口（重要）

| 判分位置 | 循环小数数学等价 | 说明 |
|---|---|---|
| 前端练习页 `practiceHelpers.js` / `QuestionCard.jsx` | 是 | 调用 `cycleDecimalEquals`，学员端即时判分正确 |
| 前端知识点页 `KnowledgePage.realJudge` | 否 | 仅文本归一比较 |
| 后端 `AnswerJudgeUtil`（交卷复核、错题订正） | 否 | 仅文本归一比较，保留 U+0307 |

- **要求**：含循环小数的题目在需要后端复核（交卷落库、错题订正）的场景下，存在等价答案被判错的风险。
- **改动前约束**：在补齐后端等价判定前，交付清单须标注哪些题的答案为循环小数；或由前端在提交前将答案归一为 STD 再上传。
- **待办**：使后端 `AnswerJudgeUtil` 与知识点页判分具备与前端一致的循环小数等价语义（列入第 11 节待补齐项）。

## 8. 导入操作规范

### 8.1 导入顺序

1. 确认学科已存在（数学为 `1002`）。
2. 导入 01 章节 → 导入 02 小节 → 导入 03 知识点（建树）。
3. 上传裁剪图片到 `POST /api/file/create`，取回 `id`，回填 04 导入版「图片」列。
4. 转换 04 交付版为 30 列导入版。
5. 导入 04 到指定题库（`repoId`）。

### 8.2 覆盖与幂等（关键事实）

- 标准 Excel 导入为**纯新增**：后端按行装配 `TemplateRequest` 时**不写 `serialNo`**，因此重复上传同一文件会产生重复题。
- 幂等覆盖仅对 `POST /api/repo/batchCreate` 的 JSON 生效：匹配键为「`serialNo` 非空且相等 + 题型相同」，命中则按 `id` 更新，否则新增。
- **推荐策略**：
  1. 首次或整批重导：先清空目标题库中对应题目，再导入；
  2. 增量修正：在阶段 5 脚本中为每道题生成稳定 `serialNo`（如「书简写-页码-题号-空序」），经 `batchCreate` 覆盖更新；
  3. 任何重导后都必须重跑第 9 节门禁并核对题量。

### 8.3 失败与回滚

- 导入校验失败时整次中止、不落库；按回报的行号修正 Excel 后重新上传。
- 图片上传失败或数量不符时，先修复图片再导入题目，避免出现缺图引用。

## 11. 历史规范差异与已知边界

1. **模板形态变更**：旧 `docs/AI教辅资料结构化任务模板.md` 使用「02 题库按题型分 sheet + 简答题 sheet + `{{IMG:}}` 占位符 + 01 知识树多 sheet 拆分导入」。现行系统为**单 sheet 30 列题目模板**，且标准导入不支持简答题、题干不内嵌占位符。本文取代旧文冲突处。
2. **系统无来源列**：书 / 页码 / 题号等出处信息在系统 30 列中无对应列，保留在交付版与 05。
3. **Excel 导入不幂等**：覆盖更新需走 `batchCreate` JSON（`serialNo` + 题型）。
4. **知识点重要度**：目录导入不含 `importance`，需导入后单独更新。
5. **知识点内容为单文本**：三段式必须写在单个单元格，系统存为 `content.points[0]`。
6. **循环小数判题不一致（待补齐）**：前端练习页支持数学等价判定，知识点页与后端 `AnswerJudgeUtil` 尚未支持，见 7.4。
7. **简答题**：题型收窄为 5 种客观题；解答题须改编或删除并记 05。
8. **判断题答案**：系统接受 `√/×` 等写法并归一到 `正确/错误`；交付建议直接写 `正确/错误` 以减少歧义。
9. **难度取值**：题目难度统一 `简单/中等/困难`（系统落 `easy/medium/hard`）；知识点 / 小节的「难度」为展示用，另有一套中文口径，勿混用。
