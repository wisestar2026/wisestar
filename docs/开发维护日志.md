## 1. 项目背景与定位

wisestar 是 fork 自开源项目「卷王 SurveyKing」（v1.10.0）的在线问卷/考试系统，改造目标是落地为 **AI 自习室系统**：

- 保留原系统的出题、组卷、答题、批改、题库管理、导入导出能力
- 新增学生答题分析的数据基础：题目三级知识点属性（学科→章节→知识点）、答题明细落库、按知识点聚合的统计接口
- 前端从原系统界面重建为 React 19 + antd 6 的自研界面（`wisestar-client`）

## 3. 本地开发环境搭建记录

> 本环境为云端 Linux（root），本地另有 Windows + VS Code + IDEA + DBeaver。以下问题均为真实踩坑记录。

### 3.1 Git 身份与推送绕墙

- **问题**：GitHub HTTPS 直连被墙，`git push` 失败
- **解决**：改用 SSH + 443 端口绕墙；Git 身份固定为 `zhanghaiyang` / `15717876985@163.com`
- **远端**：`origin` = SSH 443 绕墙；`myfork` = HTTPS/PAT

### 3.2 npm 源必须用官方源

- **问题**：华为云镜像 `registry.npmmirror.com` 拉取某些包返回 404
- **解决**：固定使用官方源 `https://registry.npmjs.org`

### 3.3 Vite 版本冲突（Windows）

- **问题**：Vite 8 在 Windows 上 rolldown 报 `UNRESOLVED_ENTRY`，`npm run dev` 起不来
- **解决**：降级 Vite 到 5.x（commit `8af0243`）
- **遗留**：云端 `node_modules` 里实际安装的是 vite 8.1.5（与 package.json 声明 `^5.4.0` 不一致）。当前云端 Linux 上 vite 8 可正常运行，但**后续重新 `npm install` 时会回退到 5.x**；若云端出现 vite 相关异常，优先检查此版本差

### 3.4 JDK 版本必须 17

- **问题**：JDK 8 下应用日志显示 Started，但 Undertow 不绑定端口，服务不可访问
- **解决**：切换 JDK 17（commit `64e7357` 配套）
- **排查经验**：服务"看似启动成功"时，先确认端口是否真的在监听，再往下查

### 3.5 后端端口显式配置

- **问题**：`server.port` 未显式设置，启动端口不稳定
- **解决**：在 `application.yml` 显式设置 `server.port`（commit `28fa9b4`）；本地 dev profile 用 7007

### 3.6 本地开发三件套

- VS Code（前端）、IDEA（后端）、DBeaver（MySQL 8）
- MySQL 8.0：root/root，库 `wisestar`，dev profile

### 阶段三：题目分析数据基础

> 对应规格文档：`.monkeycode/specs/question-analysis-data-foundation/requirements.md` 与 `design.md`

#### 3.1 题目三级知识点属性

- **改动文件**：
  - `server/rdbms/.../domain/model/Template.java`：新增 `subject`/`chapter`/`knowledgePoint`/`difficulty` 四字段
  - `server/shared/.../dto/TemplateView.java` / `TemplateRequest.java` / `TemplateQuery.java`：四字段透传与查询条件
  - `TemplateServiceImpl.listTemplate`：新增四维筛选（学科/章节/知识点/难度）
  - `SurveySchema.Attribute`：新增知识点快照字段（问卷节点 attribute 携带快照）
- **知识点结构**：学科(single) → 章节(single) → 知识点(multi)，一题可关联多个知识点；难度为 简单/中等/困难
- **知识点多值存储**：JSON 数组，如 `["函数","单调性"]`

#### 3.2 答题明细表 t_answer_detail

- **新增文件**：
  - `server/rdbms/.../domain/model/AnswerDetail.java`（实体，76 行）
  - `server/rdbms/.../mapper/AnswerDetailMapper.java`（MyBatis Mapper，12 行）
- **表结构**：id / answer_id / project_id / question_id / question_type / subject / chapter / knowledge_point / user_answer / is_correct / score / duration_ms / create_by / create_at / update_at
- **SQL 脚本**：`init-mysql.sql` / `schema-h2.sql` / `init-h2.sql` 均新增表与索引；本地迁移脚本 `migration-local-mysql-20260801.sql`（ALTER t_template + CREATE t_answer_detail）

#### 3.3 明细生成逻辑（`AnswerServiceImpl`，+141 行）

- **接口**：提交答卷（`saveAnswer`）时幂等落库——先按 answer_id 删除旧明细，再批量插入新明细
- **核心方法**：
  - `generateAnswerDetails`：解析答卷逐题生成明细
  - `formatAnswerValue`：格式化学生答案
  - `evaluateQuestionCorrect`：按题型判定对错（见下表）
  - `extractCorrectAnswers`：提取正确答案（多选无序集合比较、`\n` 分隔多正确答案）
- **对错判定规则**：

| 题型 | 规则 |
|------|------|
| 单选/下拉 (Radio/Select) | 学生答案等于正确答案（选项文本） |
| 多选 (Checkbox) | 学生答案集合与正确答案集合相等，**与顺序无关** |
| 判断 (Judge) | 学生答案等于「正确」/「错误」 |
| 填空 (FillBlank) | 去除首尾空白后相等 |
| 文本/备注/评分 (Text/Remark/Score) | 无标准答案 → `is_correct` 为 NULL，不计入正确率 |

- **幂等**：同一答卷重复提交（暂存后完成），先删后插不产生重复记录
- **快照隔离**：明细从问卷节点 attribute 快照提取知识点，历史答卷不受题库题目后续修改影响；未配置知识点的题目归「未分类」

#### 3.4 统计接口（新增）

- **新增文件**：
  - `server/shared/.../service/AnalysisService.java`（接口，32 行）
  - `server/rdbms/.../impl/AnalysisServiceImpl.java`（实现，107 行）
  - `server/api/.../api/AnalysisApi.java`（Controller，45 行）
  - `server/shared/.../dto/KnowledgePointStat.java` / `KnowledgePointQuery.java`
- **接口**：
  - `GET /api/analysis/knowledge-point/stats`：按知识点聚合统计（答题次数/正确次数/正确率，正确率四舍五入百分数，未分类归「未分类」）
  - `GET /api/analysis/knowledge-point/student-profile`：学生知识点正确率画像

#### 3.5 前端题目管理

- **改动文件**：
  - `QuestionEditModal.jsx`（+107 行）：新增知识点属性录入区（学科/章节/知识点多值 tag/难度）
  - `QuestionListPage.jsx`（+83 行）：表格新增「知识点」列 + 筛选栏（学科/章节/难度/知识点）+ 重置
  - `surveyHelpers.js`：`templateToQuestion` 快照四属性到问卷节点
- **筛选实现**：按知识点筛选时，后端 `listTemplate` 返回包含该知识点的题目列表

#### 3.6 多选题答案多选修复（两处）

- **问题**：多选题的正确答案只能选一项，无法表达多个正确选项
- **解决**：
  - `QuestionEditModal.jsx`：答案从单选改为 `mode="multiple"` 多选，存取用 `\n` 分隔字符串；`handleTypeChange` 切到 Checkbox 时 `setAnswer([])` 清空，回填时拆分数组
  - `ProjectEditPage.jsx`：答案编辑区 Checkbox 同样改多选，`updateAnswer` 把数组转 `\n` 分隔串
- **约定**：多选题答案存储格式统一为 `\n` 分隔字符串（前端数组 ↔ 后端分拆比较）

#### 3.7 导出列增强（`RepoServiceImpl.exportRepoQuestions`，+273 行）

- **改动**：各题型 sheet 统一列 = 序号/题型/所属题库/题干/选项(或空1-8)/知识点/正确答案/分值/解析/标签
- **新增辅助方法**：`questionTypeLabel` / `repoNameOf` / `knowledgePointText` / `extractCorrectAnswer`
- **正确答案兼容**：整题级（顶端 attribute，多选 `\n` 分隔逗号输出）与选项级（A/B/C 字母）两种存储，修复了「弹窗整题级答案导出为空」的 bug

#### 3.8 AnswerDetailMapper 放错包导致启动失败

- **问题**：`AnswerDetailMapper` 误放在 `domain.mapper` 包（该包是 **MapStruct** 转换 Mapper 包），启动报 `NoSuchBeanDefinitionException`
- **解决**：移动到 `cn.wisestar.server.mapper` 包（MyBatis `@MapperScan` 扫描包）后恢复正常
- **教训**：本项目两个 Mapper 概念：
  - `domain.mapper` = MapStruct 对象转换接口
  - `server.mapper` = MyBatis 数据访问接口（需被 @MapperScan 扫描）

### 阶段四：云端联调与验收

#### 4.1 云端后端构建方式

- **问题**：增量构建的 jar 里 rdbms 嵌套 jar 不更新，新代码不生效
- **解决**：云端后端**必须**用 `mvn clean package -pl api -am -DskipTests`（唯一能正确产出含新 rdbms 代码 fat jar 的方式）

#### 4.2 云端 H2 数据库维护

- **重置**：H2 库已重置为干净初始化数据（旧库备份在 `server/api/wisestar.mv.db.bak.*`），登录 admin/123456
- **启动配置**：H2 相关 schema 使用 `continue-on-error: true`，允许重复初始化
- **锚点日志**：preview 启动日志中出现 `...wisestar.mv.db` 即表示库已建好
- **验证题清理**：测试用的验证题用 API 清理，避免污染用户数据

#### 4.3 云端前端旧进程导致 HMR 失效

- **问题**：3000 端口曾跑着旧的 vite 进程，前端改动不生效（用户看到"没有变化"）
- **解决**：kill 旧进程后重启 `npm run dev`，页面/代理恢复正常（`curl http://localhost:3000/api/system` 返回 200）
- **教训**：用户反馈"界面没变化"时，第一优先检查前端 dev server 是否在跑最新代码，其次检查浏览器强刷（缓存）

#### 4.4 导出数据"只有 1 条"的排查

- **现象**：用户反馈导出的 Excel 只有 1 条数据
- **排查**：直接调用后端 `/api/repo/export`（无 repoId）能导出全部 3 道题（3 个 sheet 各 1 条：单选/多选/判断），说明后端导出逻辑正常；前端页面显示的表格列与导出列均正确
- **结论**：导出功能正常，问题属于用户侧对 sheet 结构（按题型分 sheet）的理解差异，确认无误
- **验证脚本**：`/tmp/check_export.py`、`/tmp/check_db4.py`（RSA 登录 + 手动携带 `sk-token` cookie 查询）

#### 4.5 验证脚本的 cookie 陷阱

- **问题**：Python `http.cookiejar.CookieJar` 未捕获登录返回的 `sk-token`（Set-Cookie 带 HttpOnly），后续请求 401
- **解决**：手动从 `Set-Cookie` 头用正则提取 `sk-token`，放入请求头 `Cookie` 再请求

| api Controller | `api/`：SubjectApi/ChapterApi/SectionApi/KnowledgePointApi（`@PreAuthorize("isAuthenticated()")`） |

**接口清单（REST）**：

- 学科：`GET /subject/list`（含 chapterCount）、`POST /subject/create|update|delete`
- 章节：`GET /chapter/list?subjectId=`（含 sectionCount）、`POST /chapter/create|update|delete`（删除级联小节/知识点/绑定）
- 小节：`GET /section/list?chapterId=`（含 knowledgePointCount）、`POST /section/create|update|delete`（删除级联知识点/绑定）
- 知识点：`GET /knowledge-point/list`（subjectId/chapterId/sectionId 三级可选筛选 + 分页，含三级归属名称与 questionCount）、`POST /knowledge-point/create|update|delete`（update 含 imageUrl）、`GET /knowledge-point/questions?knowledgePointId=`、`POST /knowledge-point/questions`（全量替换绑定）

**要点**：

- 小节 content/practice、知识点 content 为 **JSON 字符串透传**（前端 stringify/parse，后端只存不解析）
- 知识点图片 `imageUrl` 复用 `/api/file/create` 上传返回的 previewUrl
- 知识点题目**只能从题目库（t_template）绑定**，`saveQuestions` 先删后插（事务内全量替换）
- 列表统计（chapterCount/sectionCount/knowledgePointCount/questionCount）均按需一次批量查询 groupBy，避免 N+1
- 三级筛选（subjectId/chapterId）先在 Service 内解析出小节 id 集合再 `.in` 查询，不拼接 SQL

### 16.2 绑定弹窗题库数据源修正（根因）

- **修复**：三个绑定弹窗的 `listTemplate` 调用去掉 `shared: 1`，与题库管理页（QuestionListPage）同口径（不传 shared/repoId 时查本人创建的题目）。弹窗打开即直接显示 `t_template` 表中的题库数据。
- **验证**：`shared=1` → total=0；修复后 → total=6（首屏可见题库题目）。

### 16.3 小节页「练习设置」合并「绑定测试」

- **交互**：操作列仅保留「练习设置」一个按钮（删除「绑定测试」按钮）。

- **保存**：一次点击同时提交 `updateSection(practice)` + `saveSectionQuestions`（Promise.all），成功后刷新列表的 practice 状态与 questionCount。

### 16.4 影响面

- `SectionManagePage.jsx`：合并弹窗、删除绑定测试按钮/独立弹窗、移除未用 LinkOutlined import、更新头部注释。

## 27. 刷新/重启不登出：JWT 密钥固定 + Cookie 持久化（2026-08-21）

> 时间：2026-08-21 ｜ 范围：后端（JWT 密钥 + 登录 Cookie）

### 27.1 背景与目标

要求学员端与后台管理端刷新页面均不自动登出。排查发现两个隐患：
① JWT 签名密钥每次启动随机生成（`generateSecurityKey`），后端一旦重启所有已签发令牌全部失效（刷新/重启即登出）；
② 登录 Cookie 未设 maxAge（session cookie）。

### 27.2 后端变更

- `JwtTokenUtil`：JWT 签名密钥由「每次启动随机」改为固定配置 `wisestar.jwt.secret`（默认 `wisestar-jwt-secret-2026-fixed-key-for-preview-env-0123456789abcdef`，可经 application.yml 覆盖），后端重启后已签发令牌仍有效；移除随机密钥生成方法。
- `UserApi` 登录：登录 Cookie 加 `maxAge(7 * 24 * 3600)`（7 天持久），刷新/关闭浏览器均保持登录。

### 27.3 验证

- 打包后 jar 内确认含固定密钥（javap 常量池）；curl 登录 → 重启后端 → 旧 cookie 调 `/api/currentUser` 返回 200（重启不登出）。
- 前端登录恢复链路确认正常：App 挂载 fetchCurrentUser → AuthGuard loading 门控 → isLoggedIn 恢复，刷新不跳登录。
- 回归：角色权限 18/18；/login、/ 页面 200。
- 排查备注：node fetch 手工 Cookie 头测试不可靠（undici 不携带），权威验证须用 curl cookie jar。
