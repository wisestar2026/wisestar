# 开发规范（wisestar AI 自习室）

> 本文是仓库的开发基线，所有新增/修改代码都必须遵守。AI/自动化代理的速查版见根目录 `AGENTS.md`。
> 本文与代码同步维护；结构、接口、权限变化时，同步更新 `docs/项目结构梳理.md`、`docs/项目词典*.md` 与 `docs/开发维护日志.md`。

## 一、仓库与分支

- 仓库统一在 `main` 分支开发，**不新建开发分支、不使用 MR 流程**；提交直接推到 `origin/main`。
- 提交前逐文件 `git add <file>`，禁止 `git add -A` / `git add .`。
- 提交信息格式：`<type>(<scope>): <中文描述>`；`type ∈ feat|fix|chore|refactor|style|docs|test`，`scope` 取模块或领域（如 `student`、`math`、`db`、`practice`）。
- `commit` 与 `push` 前需与用户确认；push 不带 `-o merge_request.*` 等参数。
- 禁止提交 `*.mv.db`、`logs/`、`target/`、`.env.local`（见 `.gitignore`）。

## 二、后端分层与依赖

Maven 多模块，JDK 17，Spring Boot 2.7.7（内嵌 Undertow）。依赖方向固定：

```
api  →  rdbms  →  shared
api  →  ai
```

| 模块 | 职责 | 允许内容 |
|---|---|---|
| `shared` | 基础框架与公共契约 | 统一响应、分页、异常、鉴权、缓存、常量、DTO、Service 接口、通用工具 |
| `rdbms` | 数据访问与业务实现 | 实体、MyBatis-Plus Mapper、MapStruct 转换器、Service 实现、种子脚本 |
| `api` | Web 层与唯一启动入口 | Controller、启动类 |
| `ai` | AI 对话能力 | 独立于业务域，经 `AiChatService` 抽象接入 |

规则：

1. `shared` 不依赖其它模块；`rdbms` 只依赖 `shared`；`api` 依赖 `rdbms` 与 `ai`。
2. 服务接口定义在 `shared/.../service`，实现放在 `rdbms/.../impl`；Controller 依赖接口，不依赖实现类。
3. 禁止在 Controller 直接调用 Mapper，禁止 Service 反向依赖 Controller/DTO 之外的表现层对象。

## 三、命名与包结构

- 包根 `cn.wisestar.server`；模块内按 `core`（框架）、`domain`（领域对象）、`api`/`service`/`impl`（分层）组织。
- Java 类：Controller 后缀 `Api`（历史约定），实体无后缀，转换器后缀 `Mapper`，服务实现后缀 `ServiceImpl`。
- 新增后端业务域时，建议在同一模块内按域收敛（见第八节「胖服务与域边界」），避免大量逻辑堆在单个 `ServiceImpl`。

## 四、接口规范

1. **统一响应体** `{code, data, message}`：成功由 `CustomResponseBodyAdvice` 自动包装，`code=200`（`ResponseCode.SUCCESS`）；失败由 `GlobalExceptionHandler`、`RestAuthenticationEntryPoint` 构造，HTTP 状态仍为 200，业务结果靠 `code` 表达。
   - 注意：`ApiResponse` 类注释里的「0 表示成功」是历史描述，实际以 `ResponseCode.SUCCESS = 200` 为准。
2. **分页** 统一返回 `PaginationResponse{total, list, current, pageSize}`，查询入参用 `current` + `pageSize`。
3. **异常** 业务异常抛自定义异常（`shared/.../core/exception`），由全局处理器转换为 `{code, message}`；禁止在 Controller 内 try/catch 后手工拼响应。
4. **参数校验** 用 `@Valid` + 校验注解（`@NotNull`/`@NotBlank` 等），Controller 只做入参校验与编排，业务逻辑写在 `ServiceImpl`。
5. **对象转换** 严格 `Request → Model → View` 三层，转换用 MapStruct（`rdbms/.../domain/mapper`），禁止手写大段 `set` 拷贝。
6. **鉴权** 功能级用 `@PreAuthorize("hasAuthority('模块:动作')")`；数据级用 `@EnableDataPerm` + `DataPermAspect`（项目/问卷维度）或 `CampusScopeService`（校区维度），在服务层强制过滤。
7. 新增接口必须：登记权限点（`PermissionConsts` + 两份 SQL 脚本）、更新 `docs/项目词典-接口.md`。

## 五、数据库规范

### 5.1 结构约定

- 表名 `t_` 前缀 + 下划线小写；字段蛇形命名。
- 所有业务表统一审计列（继承 `BaseModel`）：`id`（雪花 `ASSIGN_ID`）、`create_at`、`create_by`、`update_at`、`update_by`、`is_deleted`（逻辑删除），由 `MyMetaObjectHandler` 自动填充。
- 主键 `varchar(64)`；金额/时长等用整数或定点，禁止浮点做金额。
- 类型统一 `utf8mb4` / `utf8mb4_bin`；时间戳 `timestamp` 带默认值与 `ON UPDATE`。
- **多值与引用**：跨表引用一律用关联表 + ID（如 `t_knowledge_point_question`、`t_tag`），禁止用名称文本做外键。单值可枚举状态用字典表 + 编码。多值列表允许以 JSON 数组文本直接存本表列（如 `t_template.tag`/`knowledge_point`、`t_repo.tag`），作为便捷读快照，不作为跨表引用依据；此为本项目对严格 1NF 的有意放松，新增多值关系优先建关联表。

### 5.2 索引与查询性能

- 所有用于 `WHERE` / `JOIN` / `ORDER BY` 的热点列必须建索引，命名 `idx_<表名去 t_ 前缀>_<列>`；唯一约束命名 `uk_<表简称>_<列>`。
- 组合索引遵循最左前缀，把等值条件列放前、范围/排序列放后。
- 列表查询必须分页；禁止在循环里查库（N+1），批量场景用 `IN` 或批量接口。
- 逻辑删除 `is_deleted` 参与过滤的查询，索引需带上 `is_deleted` 或采用「删除态归档」策略。

### 5.3 变更流程（新表 / 新列 / 新索引）

数据库以两份**幂等**种子脚本为准，二者必须同步修改，缺一不可：

- `server/rdbms/src/main/resources/scripts/init-h2.sql`（preview，H2）
- `server/rdbms/src/main/resources/scripts/init-mysql.sql`（dev/生产，MySQL）

新增表：

```sql
CREATE TABLE IF NOT EXISTS `t_xxx` (
  `id` varchar(64) NOT NULL,
  -- 业务列 ...
  `is_deleted` tinyint(1) NOT NULL DEFAULT 0,
  `create_at` timestamp NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `create_by` varchar(256) DEFAULT NULL,
  `update_at` timestamp NULL DEFAULT NULL ON UPDATE CURRENT_TIMESTAMP,
  `update_by` varchar(256) DEFAULT NULL,
  PRIMARY KEY (`id`),
  KEY `idx_xxx_<列>` (`<列>`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_bin;
```

新增列：`ALTER TABLE ... ADD COLUMN IF NOT EXISTS ...`；新增索引：`CREATE INDEX IF NOT EXISTS idx_xxx_col ON t_xxx(col);`。
内置权限：`INSERT ... WHERE NOT EXISTS` + 内置角色 `UPDATE` 收敛（可重复执行）。

流程约束：

1. 先改脚本，再改实体（`domain/model`，继承 `BaseModel`）与业务代码。
2. 改完后必须重建并重启预览后端，确认幂等脚本可重复执行不报错。
3. 预览库有数据变更时，按第六节重导 H2 快照并提交。

## 六、数据与快照

- 预览环境用 H2 文件库（`server/api/wisestar.mv.db`，gitignore）。容器重建会丢数据，持久化靠 SQL 快照。
- 快照流程：**停止后端** → `server/db-export.sh` → 提交 `server/db-snapshot/wisestar.sql`；`server/start-preview.sh` 在库缺失时自动导入。
- H2 文件库单进程独占；禁止启用 `AUTO_SERVER`（容器主机名解析会失败）。
- 数据修正优先走业务 API（`/update` 等，null 字段忽略），避免直接改库。

## 七、前端规范

- 技术栈 React 19 + antd 6 + zustand + Vite；源码根 `wisestar-client/src`。
- 目录：`api/`（接口封装）、`pages/`（页面）、`components/`（可复用组件）、`stores/`（zustand）、`utils/`（工具）。
- **所有 HTTP 调用经 `src/api/request.js`**，响应已由拦截器解包为 `data`；上传类 multipart 接口除外。
- 页面按端区分：管理端 `pages/*`，学员端 `pages/student/*`；路由集中在 `App.jsx`，菜单在 `components/layout/MainLayout.jsx` 并按 `required` 权限点过滤。
- 权限按钮用 `utils/usePermission`；路由级用 `components/common/AuthGuard`。
- 样式：学员端沿用海洋童趣风格（`pages/student/student.css`、`EnglishCenterPage.css`）；管理端用 antd 组件，避免大段内联样式。
- 新增页面必须：在 `App.jsx` 注册路由、在 `MainLayout` 挂菜单（如需）、补 `required` 权限点。
- 数学/富文本统一走 `components/common/RichContent.jsx`（支持 `$LaTeX$`、图片、循环小数）；填空作答符号用 `MathSymbolBar`，循环小数用 `CycleDecimalInput`。

## 八、日志规范

- 统一用 Lombok `@Slf4j` 的 `log`；**禁止 `System.out.println` 与 `e.printStackTrace()`**。
- 级别约定：
  - `error`：影响主流程的异常，必须带异常对象（`log.error("...", e)`）与关键上下文（id/参数）。
  - `warn`：可恢复的异常、兜底分支、外部依赖失败降级。
  - `info`：关键业务动作与状态变化（登录、导入导出、交卷判分、奖励结算、AI 调用起止），保持简短、字段化。
  - `debug`：仅开发排查用，禁止在生产高频路径输出大对象。
- 日志要「完整但不冗余」：一条关键路径一到两条 info；禁止在循环内逐条打印。
- 敏感信息（密码、token、手机号）禁止入日志。

## 九、胖服务与域边界

- 单个 `ServiceImpl` 承担多个业务域时，按域拆分为多个服务（接口在 `shared`、实现在 `rdbms`），Controller 只编排。
- 前端页面超过约 600 行时，抽出子组件/子 hook 到 `components/` 或同域目录。
- 跨域协作走服务接口，禁止直接 new 其它域的 Service 实现。

## 十、测试与验证

改动后至少完成与改动面匹配的验证：

- 后端：`cd server && mvn clean package -pl api -am -DskipTests` 必须构建通过；启动后对受影响接口用 curl（cookie jar）冒烟。
- 数据库：幂等脚本重复执行不报错；H2/MySQL 两份脚本结构一致。
- 前端：`cd wisestar-client && npm run build` 通过；涉及交互的功能在预览页人工确认。
- 提交前 `git status` 确认只包含预期文件。
