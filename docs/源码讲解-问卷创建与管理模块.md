# 问卷创建与管理模块 -- 源码深入讲解

> 本文档面向编程新手，用通俗易懂的语言逐层拆解 SurveyKing 项目中"问卷创建与管理"模块的完整源码逻辑。

## 一、全景图：一个请求的旅程

把后端想象成一个餐厅后厨，当你（前端）点了一份"创建问卷"套餐：

```
你（前端）                    餐厅后厨（后端）
   │                              │
   │ POST /api/project/create     │
   │ {"name":"满意度调查",...}     │
   │ ─────────────────────────>   │
   │                              ├── ProjectApi（接待员：收单、验权限）
   │                              │   @PreAuthorize("project:create")  ← 你有权限吗？
   │                              │
   │                              ├── ProjectServiceImpl（厨师：做菜）
   │                              │   1. 把原材料(ProjectRequest)洗干净(fromRequest)
   │                              │   2. 分配盘子编号(generateProjectId)
   │                              │   3. 排优先级(文件夹放前面，问卷放后面)
   │                              │   4. 入锅(save -> INSERT SQL)
   │                              │   5. 登记主人(添加OWNER参与者)
   │                              │
   │                              ├── ProjectMapper（仓库管理员：查库存）
   │                              │   执行 INSERT INTO t_project ...
   │                              │
   │   {"id":"abc123",...}        │
   │ <─────────────────────────   │
```

## 三、逐文件拆解

### 3.1 BaseModel.java -- 所有数据表的"公共身份证"

路径：`server/rdbms/src/main/java/cn/surveyking/server/core/model/BaseModel.java`

```java
@Data
public class BaseModel {

    // 自动生成雪花算法ID（全局唯一的长数字）
    @TableId(type = IdType.ASSIGN_ID)
    private String id;

    // 创建时间和创建人（插入时自动填充）
    @TableField(fill = FieldFill.INSERT)
    private Date createAt;
    @TableField(fill = FieldFill.INSERT)
    private String createBy;

    // 修改时间和修改人（更新时自动填充）
    @TableField(fill = FieldFill.UPDATE)
    private Date updateAt;
    @TableField(fill = FieldFill.UPDATE)
    private String updateBy;

    // 逻辑删除标记：deleted=true 表示"已删除"但不真删
    @TableLogic
    @JsonIgnore
    @TableField(value = "is_deleted", select = false)
    private Boolean deleted = false;
}
```

**通俗解释**：就像每个中国公民都有身份证号、出生日期一样，数据库里每张表的数据都"继承"了这个公共身份证。`@TableLogic` 的意思是：点击"删除"时不是真的把数据从硬盘擦掉，而是打个标记 `deleted=true`，数据还在，可以恢复。

### 3.2 Project.java -- t_project 表的"图纸"

路径：`server/rdbms/src/main/java/cn/surveyking/server/domain/model/Project.java`

```java
@Data
@TableName(value = "t_project", autoResultMap = true)
@EqualsAndHashCode(callSuper = false)
public class Project extends BaseModel {

    private String name;                 // 问卷名称
    private String parentId;             // 父文件夹ID（0表示根目录）
    private ProjectModeEnum mode;        // survey=问卷, exam=考试, folder=文件夹
    private Integer status;              // 1=已发布, 0=未发布
    private Long priority;              // 排序优先级（值越小越靠前）

    // 问卷内容存在一个大 JSON 字段里
    @TableField(typeHandler = JacksonTypeHandler.class, jdbcType = JdbcType.LONGVARCHAR)
    private SurveySchema survey;

    // 问卷设置也存在一个大 JSON 字段里
    @TableField(typeHandler = JacksonTypeHandler.class, jdbcType = JdbcType.LONGNVARCHAR)
    private ProjectSetting setting;

    @TableField(fill = FieldFill.INSERT)
    private Date createAt;

    @TableField(fill = FieldFill.UPDATE)
    private Date updateAt;
}
```

**核心设计亮点**：`survey` 和 `setting` 字段存的是 JSON 字符串。

**为什么要用 JSON？** 因为问卷结构千变万化 -- 有的问卷只有 3 道选择题，有的有 50 道各种题型混搭。如果每张表存一种题型，会有几十张表，SQL 查询会非常复杂。用 JSON 就像用一个大箱子：不管问卷里有什么题型、什么结构，塞进箱子里，存到数据库的一个字段里。读取时再打开箱子，变回 Java 对象。

`JacksonTypeHandler` 就是负责"装箱"和"拆箱"的工人：存的时候把 Java 对象变成 JSON 字符串，取的时候把 JSON 字符串变回 Java 对象。

### 3.3 SurveySchema.java -- 问卷的核心数据结构

路径：`server/shared/src/main/java/cn/surveyking/server/domain/dto/SurveySchema.java`

这是最核心的类（568 行），但核心概念很简单。它是一个**树形结构**：

```java
@Data
@Builder
public class SurveySchema implements Serializable {

    private String id;                    // 这个节点的 ID
    private String title;                 // 显示的文字
    private QuestionType type;            // 是什么题型
    private Attribute attribute;          // 各种配置（必填、宽度、分值...）
    private List<SurveySchema> children;  // 子题目（这就是递归！）
    private List<DataSource> dataSource;  // 选项列表（如["满意","不满意"]）
    private List<Row> row;                // 矩阵题的行定义
}
```

**树的比喻**：一棵树（整个问卷），树干是第一页，每个树枝是分页，长在树枝上的叶子是题目，叶子上的脉络是选项。

```
问卷（根节点，type=Survey）
├── 分页1（type=Pagination）
│   ├── 单选题："你对公司满意吗？"（type=Radio）
│   │   ├── 选项：满意
│   │   └── 选项：不满意
│   └── 填空题："请说明原因"（type=FillBlank）
├── 分页2（type=Pagination）
│   └── 打分题："给食堂打分"（type=Score）
└── 分页3（type=Pagination）
    └── 上传题："上传照片"（type=Upload）
```

在数据库里存成 JSON 就是：

```json
{
  "id": "survey_root",
  "type": "Survey",
  "children": [
    {
      "id": "page1",
      "type": "Pagination",
      "children": [
        {
          "id": "q1",
          "type": "Radio",
          "title": "你对公司满意吗？",
          "attribute": { "required": true },
          "dataSource": [
            { "label": "满意", "value": "1" },
            { "label": "不满意", "value": "2" }
          ]
        }
      ]
    }
  ]
}
```

**支持的题型一览**（`QuestionType` 枚举）：

| 类别 | 题型 | 枚举值 | 说明 |
|------|------|--------|------|
| 基础选择题 | 单选、多选、下拉、级联 | Radio, Checkbox, Select, Cascader | 最常用的四种选择方式 |
| 填空题 | 短填空、长文本、多填空、横向填空 | FillBlank, Textarea, MultipleBlank, HorzBlank | 不同长度的填空场景 |
| 矩阵题 | 矩阵单选、矩阵多选、矩阵填空、矩阵打分、矩阵NPS | MatrixRadio, MatrixCheckbox, MatrixFillBlank, MatrixScore, MatrixNps | 表格形式的批量题目 |
| 打分题 | 打分、NPS净推荐值 | Score, Nps | 数值型评分 |
| 上传题 | 文件上传、签名、条码 | Upload, Signature, Barcode | 收集文件/图片 |
| 特殊题 | 富文本、地址、选人、选部门、判断题 | RichText, Address, User, Dept, Judge | 特殊场景 |
| 辅助元素 | 分页、备注、分割线、问卷容器 | Pagination, Remark, SplitLine, Survey | 不参与答题，只影响布局 |

**数据题型（会实际收集答案）** 和 **空题型（只影响布局）**：

- 数据题型：FillBlank, Radio, Checkbox, Select, Score 等 -- 用户填的数据会被保存
- 空题型：Pagination（分页）, Remark（备注）, SplitLine（分割线） -- 只影响页面结构

### 3.4 ProjectRequest.java -- 前端传过来的"送菜单"

路径：`server/shared/src/main/java/cn/surveyking/server/domain/dto/ProjectRequest.java`

```java
@Data
public class ProjectRequest {
    private String id;              // 创建时为空，修改时有值
    private String name;            // 问卷名称
    private ProjectModeEnum mode;   // survey / exam / folder
    private SurveySchema survey;    // 问卷结构（JSON树）
    private ProjectSetting setting; // 问卷设置
    private Integer status;         // 1=已发布 0=草稿
```

**通俗解释**：前端发来的 JSON 会自动变成这个 Java 对象。比如前端发 `{"name":"满意度调查","mode":"survey"}`，Spring Boot 会自动 new 一个 ProjectRequest，把 `name` 设成"满意度调查"，`mode` 设成 `survey`。

### 3.5 ProjectView.java -- 返回给前端的"出菜单"

路径：`server/shared/src/main/java/cn/surveyking/server/domain/dto/ProjectView.java`

```java
@Data
public class ProjectView {
    // 基础字段（同 ProjectRequest）
    private String id;
    private String name;
    private ProjectModeEnum mode;
    private Integer status;
    private SurveySchema survey;
    private ProjectSetting setting;

    // 额外统计信息（数据库里没有，实时计算）
    private Long total;                 // 总答题数
    private Integer totalOfToday;       // 今日答题数
    private Long lastUpdate;            // 最近更新时间
    private Long averageDuration;       // 平均填写时长

    private Date createAt;
    private Date updateAt;
    private String parentId;
```

**为什么要有 View？** 数据库里没有 `totalOfToday` 这个字段，是在查询时实时计算的。前端需要的"展示数据"和数据库里的"存储数据"不一样，所以分开两个类。

### 3.6 ProjectViewMapper.java -- 翻译官

路径：`server/rdbms/src/main/java/cn/surveyking/server/domain/mapper/ProjectViewMapper.java`

```java
@Mapper
public interface ProjectViewMapper extends BaseModelMapper<ProjectRequest, ProjectView, Project> {
    // MapStruct 自动生成实现代码！
    Project fromRequest(ProjectRequest request);   // 请求 -> 数据库实体
    ProjectView toView(Project model);              // 数据库实体 -> 视图

    // 公开问卷视图（对答题者展示），会隐藏密码等敏感设置
    @Mapping(target = "setting", source = "setting.answerSetting")
    @Mapping(target = "setting.answerSetting.password", ignore = true)
    PublicProjectView toPublicProjectView(ProjectView project);

    // 考试模式下自动去掉正确答案信息（防止作弊）
    @AfterMapping
    default void calledWithSourceAndTargetType(ProjectView source, @MappingTarget PublicProjectView view) {
        if (考试模式 && 非练习模式) {
            去掉 schema 里的正确答案;
        }
        if (考试模式 && 随机题目顺序) {
            打乱题目顺序;
        }
    }
}
```

**通俗解释**：就像你出国旅游需要翻译，这里的三种"语言"是：
- `ProjectRequest` 是前端说的语言（请求）
- `Project` 是数据库说的语言（实体）
- `ProjectView` 是前端能看懂的语言（展示）

MapStruct 编译时自动生成翻译代码，不用手写 `project.setName(request.getName())` 这种繁琐的代码。`@AfterMapping` 表示翻译完之后再做几道"后期处理"：考试模式下删掉正确答案、随机排列题目顺序。

**继承链解释**：
- `BaseService<ProjectMapper, Project>` 继承自 MyBatis-Plus 的 `ServiceImpl`
- 自动获得的方法：`save()`（新增）、`getById()`（查单条）、`page()`（分页查）、`count()`（计数）、`updateById()`（更新）、`removeById()`（逻辑删除）
- 这就是为什么 ServiceImpl 里看不到手写 SQL -- MyBatis-Plus 帮你写好了

#### 3.8.2 创建问卷 -- addProject() 逐行讲解

```java
@Override
public ProjectView addProject(ProjectRequest request) {

    // [步骤1] 翻译：把前端的 ProjectRequest 转成数据库的 Project 实体
    // 比如 request.getName()="满意度调查" -> project.setName("满意度调查")
    Project project = projectViewMapper.fromRequest(request);

    // [步骤2] 生成唯一ID：6位随机字符串，不以数字开头，不和已有ID重复
    String projectId = generateProjectId();
    project.setId(projectId);

    // [步骤3] 把生成的ID同步到问卷Schema里
    // 这样问卷JSON结构里面也有这个ID，前后关联
    if (project.getSurvey() != null) {
        project.getSurvey().setId(projectId);
    }

    // [步骤4] 设置排序优先级
    if (ProjectModeEnum.folder.equals(request.getMode())) {
        // 文件夹排前面：priority = 1, 2, 3, 4, ...
        // 统计现有文件夹数量，新文件夹排在最后
        project.setPriority(
            count(查所有 folder 类型) + 1
        );
    } else {
        // 问卷/考试排后面：priority = 1001, 1002, 1003, ...
        // 从 1000 起算，确保永远排在文件夹后面
        project.setPriority(
            count(查所有非 folder 类型) + 1000
        );
    }

    // [步骤5] 保存到数据库
    // MyBatis-Plus 自动生成：INSERT INTO t_project (...) VALUES (...)
    save(project);

    // [步骤6] 添加项目参与者：把创建者设为 OWNER
    ProjectPartnerRequest partnerRequest = new ProjectPartnerRequest();
    partnerRequest.setType(ProjectPartnerTypeEnum.OWNER.getType());  // 类型=拥有者
    partnerRequest.setProjectId(project.getId());
    partnerRequest.setUserIds(Collections.singletonList(
        SecurityContextUtils.getUserId()  // 当前登录用户的ID
    ));
    projectPartnerService.addProjectPartner(partnerRequest);

    // [步骤7] 把存好的数据翻译回前端格式，返回
    return projectViewMapper.toView(project);
}
```

**通俗版流程**：

```
前端说："帮我创建一份满意度调查问卷"

后端做的事：
  1. 洗菜          → fromRequest(): 把前端数据转成数据库格式
  2. 生火起锅       → generateProjectId(): 生成6位唯一ID
  3. 贴标签         → survey.setId(): 把ID同步到问卷结构里
  4. 排位置         → 文件夹 priority=1,2,3 / 问卷 priority=1001,1002
  5. 入锅          → save(): INSERT INTO t_project ...
  6. 写归属         → addProjectPartner(): INSERT INTO t_project_partner
  7. 出锅上菜       → toView(): 转成前端格式返回
```

#### 3.8.3 生成唯一ID -- generateProjectId()

```java
private String generateProjectId() {
    // NanoIdUtils.randomNanoId(6): 生成6位随机字符串，如 "a3Kf9x"
    String projectId = NanoIdUtils.randomNanoId(6);

    // 规则1: 不能以数字开头
    // 原因：后续工作流引擎保存 XML 文件时，数字开头的 ID 会出问题
    if (Character.isDigit(projectId.charAt(0))) {
        return generateProjectId();  // 重试！
    }

    // 规则2: 不能和已有ID重复
    if (getById(projectId) != null) {
        return generateProjectId();  // 重试！
    }

    return projectId;
}
```

**递归重试**：如果生成的 ID 不满足条件，就重新生成，直到符合要求为止。由于 6 位随机字符串的碰撞概率很低，通常一次就成功。

#### 3.8.4 列出问卷列表 -- listProject()

```java
@Override
public PaginationResponse<ProjectView> listProject(ProjectQuery query) {

    // 构建一个带很多条件的查询
    Page<Project> page = pageByQuery(query,
        Wrappers.<Project>lambdaQuery()
            // 模糊搜索：名称包含关键词
            .like(isNotBlank(query.getName()), Project::getName, query.getName())
            // 精确匹配：指定上级文件夹
            .eq(isNotBlank(query.getParentId()), Project::getParentId, query.getParentId())
            // 兜底：没指定父文件夹时，查根目录下的（parentId 为空或为 "0"）
            .and(isBlank(query.getParentId()),
                c -> c.isNull(Project::getParentId).or().eq(Project::getParentId, "0"))
            // 按模式筛选
            .eq(query.getMode() != null, Project::getMode, query.getMode())
            // 数据权限：只查我是 OWNER 或协作者的项目
            .exists("SELECT 1 FROM t_project_partner t WHERE t.type in (1,2) AND t.user_id = {0} AND t.project_id = t_project.id",
                SecurityContextUtils.getUserId())
            // 排序：文件夹排前面，然后按创建时间倒序
            .last("ORDER BY CASE WHEN mode = 'folder' THEN 0 ELSE 1 END ASC, create_at DESC")
    );

    // 把数据库实体翻译成前端视图
    PaginationResponse<ProjectView> result = new PaginationResponse<>(
        page.getTotal(),                          // 总记录数
        projectViewMapper.toView(page.getRecords()) // 当前页数据
    );

    // 给每个项目补充统计信息
    result.getList().forEach(view -> {
        if (ProjectModeEnum.folder.equals(view.getMode())) {
            // 文件夹：统计里面有多少子项目
            view.setTotal(count(查 parentId=本文件夹ID 的项目));
        } else {
            // 问卷/考试：统计有多少人答过题
            view.setTotal(answerMapper.selectCount(查 projectId=本问卷ID 的答案));
        }
    });

    return result;
}
```

**链式查询解释**：`Wrappers.lambdaQuery()` 是 MyBatis-Plus 提供的一种"拼积木"写法。每个 `.eq()`、`.like()` 就像一块积木：

```
.like(条件为真才生效, 按哪个字段查, 查什么值)
.eq(条件为真才生效, 按哪个字段查, 查什么值)
```

比如 `.like(isNotBlank("满意"), Project::getName, "满意")` -- 只有 name 不为空时才加上这个条件。

**数据权限的 SQL 写法**：`.exists(...)` 相当于执行了一条子查询，确保只返回当前用户有权限查看的项目。

**排序技巧**：`CASE WHEN mode = 'folder' THEN 0 ELSE 1 END` 让文件夹排前面（值为 0），问卷排后面（值为 1），再按创建时间从新到旧排序。

#### 3.8.5 更新问卷 -- updateProject()

```java
@Override
@SneakyThrows
public void updateProject(ProjectRequest request) {
    // synchronized: 防止多个人同时修改同一个问卷导致数据错乱
    synchronized (request.getId().intern()) {
        Project project = projectViewMapper.fromRequest(request);

        // 如果前端只传了 settingKey 和 settingValue，表示只改某一项设置
        if (request.getSettingKey() != null) {
            // 安全检查：只允许更新 ProjectSetting 类里存在的字段
            validateSettingKey(request.getSettingKey());

            // 从数据库取出当前的完整设置
            ProjectSetting setting = getById(request.getId()).getSetting();

            // 用 SpEL 表达式动态修改某个字段
            // 比如 settingKey="examSetting.randomOrder", settingValue=true
            // 相当于执行: setting.getExamSetting().setRandomOrder(true)
            spelParser.parseExpression(request.getSettingKey())
                      .setValue(setting, request.getSettingValue());

            project.setSetting(setting);

            // 如果改的是 status 字段，同步更新
            if ("status".equals(request.getSettingKey())) {
                project.setStatus((Integer) request.getSettingValue());
            }
        }

        // MyBatis-Plus 自动生成: UPDATE t_project SET ... WHERE id=?
        updateById(project);
    }
}
```

**什么是 SpEL 表达式？** Spring Expression Language，是 Spring 提供的一种动态执行工具。它可以在运行时解析字符串表达式并执行：

- 输入：`"examSetting.randomOrder"` + `true`
- 效果：`setting.getExamSetting().setRandomOrder(true)`

**安全检查 validateSettingKey()**：遍历 `ProjectSetting` 类的所有字段，确保前端传的 `settingKey` 是合法字段名，防止恶意传入危险表达式。

#### 3.8.6 删除流程（三步走）

```java
// 第一步：软删除 -- 进回收站
@Override
public void deleteProject(ProjectRequest request) {
    // MyBatis-Plus 逻辑删除：把 deleted 字段设为 true
    removeById(request.getId());
}

// 第二步：查看回收站
@Override
public List<ProjectView> getDeleted(ProjectQuery query) {
    List<ProjectView> list = projectViewMapper.toView(
        getBaseMapper().selectLogicDeleted(SecurityContextUtils.getUserId())
    );
    list.forEach(view -> {
        if (!ProjectModeEnum.folder.equals(view.getMode())) {
            view.setTotal(answerMapper.selectCount(
                Wrappers.<Answer>lambdaQuery().eq(Answer::getProjectId, view.getId())
            ));
        }
    });
    return list;
}

// 第三步A：恢复 -- 从回收站捞回来
@Override
public void restoreProject(ProjectRequest request) {
    // 把 deleted 改回 false
    getBaseMapper().restoreProject(request.getIds());
}

// 第三步B：彻底删除 -- 无法恢复
@Override
public void batchDestroyProject(ProjectRequest request) {
    // 物理删除：数据库里真的删掉
    getBaseMapper().batchDestroy(request.getIds());
    // 同时删掉关联的参与者数据
    ProjectPartnerRequest deletePartnerRequest = new ProjectPartnerRequest();
    deletePartnerRequest.setProjectIds(request.getIds());
    projectPartnerService.deleteProjectPartner(deletePartnerRequest);
}
```

**删除机制类比 Windows 回收站**：

```
用户点击"删除"
  → removeById()               ✅ 进回收站（deleted=true，可恢复）

用户在回收站点"恢复"
  → restoreProject()           ✅ 恢复（deleted=false）

用户在回收站点"彻底删除"
  → batchDestroyProject()      ❌ 永久删除（物理删除，不可恢复）
```

## 六、核心设计要点速记

| 要点 | 说明 |
|------|------|
| 问卷用 JSON 存储 | 问卷结构（SurveySchema）是树形结构，通过 JacksonTypeHandler 序列化为 JSON 字符串存到数据库的一个字段里 |
| 继承 BaseModel | 所有实体类共享 id、createAt、createBy、updateAt、updateBy、deleted 六个字段 |
| 逻辑删除 | `@TableLogic` 标记，删除时只改 deleted 字段，不进回收站的数据可以恢复 |
| 优先级设计 | 文件夹 priority=1,2,3，问卷 priority=1001,1002，保证文件夹永远排在前面 |
| 数据权限 | `@EnableDataPerm` 切面注解，确保用户只能操作自己的数据 |
| 参与者机制 | 问卷创建者是 OWNER，还能添加协作者（COLLABORATOR）和答题人（RESPONDENT） |
| 唯一ID生成 | 6位 NanoId，不以数字开头（兼容工作流 XML），递归重试保证不重复 |
| SpEL 局部更新 | 前端可以只传 settingKey+settingValue，后端用 SpEL 表达式精准修改某个设置项 |
